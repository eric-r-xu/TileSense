# Deploying the TileSense Flutter client

This app is a single Flutter codebase (`flutter_client/`) that ships to the web,
Android, and iOS from the same `lib/`. This document covers building and
releasing each target.

## Prerequisites

| Target | Needs |
| --- | --- |
| Web | Flutter SDK ≥ 3.3, any OS, a static host |
| Android | Flutter SDK, Android Studio or the Android command-line tools + a JDK 17, a keystore, a Google Play Console account ($25 one-time) for store release |
| iOS | **macOS**, Xcode ≥ 15, CocoaPods (`sudo gem install cocoapods`), an Apple Developer Program membership ($99/year) for TestFlight / App Store |

Verify the toolchain:

```sh
flutter doctor -v
```

If the platform folders are missing (fresh clone), regenerate them without
touching `lib/`:

```sh
cd flutter_client
flutter create --org com.tilesense --platforms=web,android,ios .
flutter pub get
```

## Shared setup (do this once)

### App identity

- **Name shown to users**: set in each platform (see below). Keep it consistent,
  e.g. `TileSense`.
- **Bundle / application id**: pick a reverse-DNS id you control, e.g.
  `com.tilesense.tilesense`. It must match on Android (`applicationId`) and iOS
  (`PRODUCT_BUNDLE_IDENTIFIER`) if you want one identity across stores, but the
  two stores are otherwise independent.

### Version and build number

Both come from `pubspec.yaml`:

```yaml
version: 0.2.0+2
#        ^^^^^  ^-- build number  (Android versionCode / iOS CFBundleVersion)
#        └------- version name    (Android versionName  / iOS CFBundleShortVersionString)
```

Bump the build number (`+N`) on **every** upload to a store; bump the version
name for user-visible releases. `flutter build` reads these automatically;
override at build time with `--build-name=X.Y.Z --build-number=N` if needed.

### Launcher icon and splash (optional but recommended)

Add dev dependencies and a source icon (`assets/icon/icon.png`, 1024×1024, no
transparency for iOS):

```yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.1
  flutter_native_splash: ^2.4.1

flutter_launcher_icons:
  image_path: "assets/icon/icon.png"
  android: true
  ios: true
  web: { generate: true }
  remove_alpha_ios: true

flutter_native_splash:
  color: "#063a3a"
```

```sh
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

## Web

### Build

```sh
flutter build web --release
# output: build/web/
```

Renderer choice:

- Default (**CanvasKit**) — pixel-consistent, larger first download (~1.5 MB wasm
  brought in on demand). Best for this app's dense tile tables.
- `--web-renderer html` — smaller, uses the DOM/Canvas 2D; text and emoji
  rendering can differ per browser. Fine as a fallback.
- Newer Flutter also offers `flutter build web --wasm` (whole app compiled to
  WasmGC). Test it — `flutter build web` already prints a "Wasm dry run
  succeeded" hint for this project.

### Sub-path hosting

If the site is served from `https://example.com/riichi/` rather than the domain
root, set the base href:

```sh
flutter build web --release --base-href /riichi/
```

### Host it

`build/web/` is a plain static bundle. Any of:

- **GitHub Pages**: push `build/web/` to a `gh-pages` branch (or use the
  `peaceiris/actions-gh-pages` action). Repo-hosted pages live at
  `https://<user>.github.io/<repo>/`, so build with
  `--base-href /<repo>/`.
- **Netlify / Vercel / Cloudflare Pages**: build command
  `flutter build web --release`, publish directory `build/web`. Add a redirect so
  deep links fall back to `index.html`:
  - Netlify `build/web/_redirects`: `/*  /index.html  200`
- **Firebase Hosting**:
  ```sh
  npm i -g firebase-tools
  firebase init hosting        # public dir: build/web ; single-page app: yes
  flutter build web --release
  firebase deploy --only hosting
  ```

### PWA / offline

`flutter create` already emits `web/manifest.json` and a service worker. To make
it installable and offline-capable:

- Edit `web/manifest.json`: `name`, `short_name`, `background_color` (`#063a3a`),
  `theme_color`, and the icon set (regenerated by `flutter_launcher_icons` if you
  set `web: { generate: true }`).
- The generated service worker caches the app shell; a repeat visit works
  offline. Bump `version` in `pubspec.yaml` so clients pick up new builds
  (Flutter stamps the service worker with it).

## Android

### Configure `android/app/build.gradle` (or `build.gradle.kts`)

```gradle
android {
    namespace = "com.tilesense.tilesense"
    defaultConfig {
        applicationId = "com.tilesense.tilesense"
        minSdk = 23          // Flutter's current floor is 21; 23 covers ~99% of devices
        targetSdk = flutter.targetSdkVersion   // keep current for Play submission
        versionCode = flutter.versionCode      // from pubspec "+N"
        versionName = flutter.versionName      // from pubspec "X.Y.Z"
    }
}
```

App display name: `android/app/src/main/AndroidManifest.xml`,
`<application android:label="TileSense" …>`.

This app needs **no runtime permissions** — it is fully offline. Make sure no
stray `<uses-permission>` (e.g. INTERNET, added by some plugins) is present that
you do not want; `INTERNET` is harmless and often kept for debugging.

### Signing (release)

1. Create a keystore (keep it and the passwords safe and out of git):

   ```sh
   keytool -genkey -v -keystore ~/tilesense-upload.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```

2. `android/key.properties` (git-ignored):

   ```properties
   storePassword=…
   keyPassword=…
   keyAlias=upload
storeFile=/absolute/path/tilesense-upload.jks
   ```

3. Wire it into `android/app/build.gradle` above `buildTypes`:

   ```gradle
   def keystoreProperties = new Properties()
   def keystorePropertiesFile = rootProject.file("key.properties")
   if (keystorePropertiesFile.exists()) {
       keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
   }

   android {
       signingConfigs {
           release {
               keyAlias keystoreProperties["keyAlias"]
               keyPassword keystoreProperties["keyPassword"]
               storeFile keystoreProperties["storeFile"] ? file(keystoreProperties["storeFile"]) : null
               storePassword keystoreProperties["storePassword"]
           }
       }
       buildTypes {
           release {
               signingConfig signingConfigs.release
               minifyEnabled true
               shrinkResources true
           }
       }
   }
   ```

### Build

```sh
# Play Store upload format (recommended):
flutter build appbundle --release
# -> build/app/outputs/bundle/release/app-release.aab

# Direct-install / sideload APKs, split per ABI to keep them small:
flutter build apk --release --split-per-abi
# -> build/app/outputs/flutter-apk/app-arm64-v8a-release.apk (+ armeabi-v7a, x86_64)
```

Sanity-check the release build on a device:

```sh
flutter install --release
```

### Publish to Google Play

1. Play Console → **Create app**.
2. Complete the required declarations: content rating (IARC questionnaire —
   this is a card game, no gambling with real money), data safety (this app
   collects and shares **nothing**), target audience, ads (none), privacy policy
   URL (host a short one; even "no data collected" needs a URL).
3. Upload the `.aab` to a **Closed testing** track first, add testers, then
   promote to **Production**.
4. Google re-signs with an app-signing key; your `upload` key only signs the
   upload. Keep both.

## iOS / iPhone

> Requires macOS + Xcode. There is no way to build or sign an `.ipa` on Linux or
> Windows.

### Configure the Xcode project

```sh
cd flutter_client
open ios/Runner.xcworkspace
```

In **Runner ▸ Signing & Capabilities**:

- **Team**: your Apple Developer Program team.
- **Bundle Identifier**: `com.tilesense.tilesense` (must be registered on the
  Apple Developer portal / created automatically when you check
  "Automatically manage signing").

In **Runner ▸ General**:

- **Display Name**: `TileSense`
- **Version** / **Build**: leave these to come from `pubspec.yaml`
  (`$(FLUTTER_BUILD_NAME)` / `$(FLUTTER_BUILD_NUMBER)` — the Flutter tooling sets
  them).
- **Deployment target**: iOS 13.0 or newer (Flutter's current minimum is 12).
- **Device Orientation**: this app is **landscape-only**. `main()` calls
  `SystemChrome.setPreferredOrientations([landscapeLeft, landscapeRight])`, and
  the platform configs pin it too — `ios/Runner/Info.plist`
  `UISupportedInterfaceOrientations` (iPhone and iPad) lists only the two
  landscape values, Android's `AndroidManifest.xml` activity sets
  `android:screenOrientation="sensorLandscape"`, and `web/manifest.json` sets
  `"orientation": "landscape"` (with a runtime `_LandscapeGate` prompt as the
  web fallback, since browsers can't hard-lock rotation).

`ios/Runner/Info.plist` otherwise needs no special keys — the app uses no
camera, location, network entitlements, or background modes.

### Build

```sh
flutter build ipa --release
# -> build/ios/archive/Runner.xcarchive
# -> build/ios/ipa/tilesense.ipa  (if export succeeds non-interactively)
```

If the non-interactive export can't pick a signing profile, open the archive in
Xcode's **Organizer** (`Window ▸ Organizer`) and use **Distribute App** →
*App Store Connect* or *Ad Hoc*.

### Upload to TestFlight / App Store

1. App Store Connect → **My Apps ▸ +** → new app, same bundle id.
2. Upload the build:
   - Xcode Organizer → **Distribute App → App Store Connect → Upload**, or
   - `xcrun altool --upload-app -f build/ios/ipa/*.ipa -t ios -u <apple-id> -p <app-specific-password>`,
     or the newer `xcrun notarytool`/**Transporter** app.
3. The build appears in **TestFlight** after processing (~5–30 min). Add internal
   testers immediately; external testers require a short Beta App Review.
4. For App Store release: fill in the listing, screenshots (6.7" and 5.5"
   required), age rating (card game, no real-money gambling), the privacy
   "Nutrition Label" (**Data Not Collected**), then submit for review.

## Continuous integration

Minimal GitHub Actions workflow that gates every push on analyze + tests and
publishes the web build:

```yaml
# .github/workflows/flutter.yml
name: flutter
on:
  push: { paths: ["flutter_client/**", ".github/workflows/flutter.yml"] }
  pull_request: { paths: ["flutter_client/**"] }

jobs:
  check:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: flutter_client } }
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with: { channel: stable }
      - run: flutter pub get
      - run: flutter analyze
      - run: flutter test
      - run: flutter build web --release --base-href /TileSenseFlutter/
      - uses: peaceiris/actions-gh-pages@v4
        if: github.ref == 'refs/heads/master'
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: flutter_client/build/web
```

Store releases (Android `.aab`, iOS `.ipa`) are usually a separate,
manually-triggered workflow because they need secrets (keystore, App Store
Connect API key). `fastlane` (`supply` for Play, `deliver`/`pilot` for App
Store) is the standard tool if you want them automated.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Web: blank page under a sub-path | rebuild with `--base-href /<path>/` (leading and trailing slash) |
| Web: deep-link reload 404s | add the SPA fallback redirect to `index.html` (see host notes) |
| Web: tile glyphs look different across browsers | you are on the HTML renderer; drop `--web-renderer html` to use CanvasKit |
| Web: tiles render blank (typically Chrome on Android) | the bundled `MahjongTiles` font failed to load — confirm `assets/fonts/MahjongTiles-Regular.ttf` is in the build and listed in `FontManifest.json`; regenerate it per `assets/fonts/README.md` if missing |
| Web: spoken lines don't play on mobile | audio unlocks only after the first tap anywhere in the app (`Sfx.unlock`); a tap that lands before the Flutter view is interactive won't count — tap again |
| Android: `Execution failed … lStar` / AGP errors | update `android/settings.gradle` Android Gradle Plugin + Gradle wrapper to the versions `flutter doctor` recommends |
| Android: `keystore not found` on release build | check `storeFile` in `key.properties` is an absolute path and the file exists |
| Android: Play rejects "debuggable" APK | you built `apk` without `--release`, or `key.properties` was absent so it fell back to the debug signing config |
| iOS: `No profiles for 'com.…' were found` | open `ios/Runner.xcworkspace`, enable *Automatically manage signing*, pick your Team |
| iOS: `CocoaPods not installed` | `sudo gem install cocoapods && (cd ios && pod install)` |
| iOS: archive missing from Organizer | build for a *Generic iOS Device* / *Any iOS Device (arm64)*, not a simulator |
| Any: stale build after dependency change | `flutter clean && flutter pub get` |
