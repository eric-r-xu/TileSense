# TileSense seat-0 statistics report

Engine commit `d53ec82` (the last commit to change the game engine). Seat 0 is the decision maker; seats 1–3 are the shipped `SimpleBot`. Every row uses the same **200 consecutive seeds, 500000–500199**. Game-by-game results live in the local `tilesense-sim` PostgreSQL database (`reports/sim_schema.sql`); this file is generated by `reports/sim_report.py`.

- **Win Rate** / **Deal-in Rate**: seat-0 wins (or deal-ins) ÷ hands played, per game.
- **Ending Points (% vs start)**: 100 · (end − start) / start, where start is 25,000 (Riichi) or 1,000 chips (Hong Kong, Taiwanese).
- **Ending Placement**: 1–4, ties split (e.g. 2.5).
- **SD**: standard deviation of the per-seed values. **SE** = SD/√n. **CV** = SD/|Mean|. **SD UCL**: one-sided 80% upper confidence limit of the SD.
- **Guide rows** are compared with the Simple Bot row of the same variant and length on the same seeds (paired). **ρ**: correlation between the guide's and the bot's value on each seed. **Δ**: mean of guide − bot. **Holm p**: two-sided, Holm-adjusted within each variant, length and metric.
- **Seeds needed** to detect an effect δ (two-sided α = 0.05, power 0.80). δ is 10 percentage points of stack for Ending Points and 10% of the bot's mean otherwise. *Unpaired* ignores the shared seeds. *Paired* uses the SD of the per-seed differences. *Paired (UCL)* uses that SD's 80% upper confidence limit, so a CV estimated from a small sample does not under-power the plan; this is the one to use.
- Hong Kong and Taiwanese pin Style to Balanced and Strategy to Points in the game, so only Focus varies there.
